# 搜救資訊離線版

手機用的搜救案件資訊 PWA：案件摘要、離線地圖（預設魯地圖）、GPS／TWD97 座標工具、任務分組與檢查清單。加到主畫面後，沒有網路也能使用。

- **App 網址**：[https://ben901227.github.io/rescue-offline/](https://ben901227.github.io/rescue-offline/)（手機開啟後「加入主畫面」即可離線使用）
- **使用教學**：[https://ben901227.github.io/rescue-offline/guide.html](https://ben901227.github.io/rescue-offline/guide.html)（圖文、大字，App 右上角「?」也能打開）

## 個資原則

- 網站本身**不含任何案件資料**。案件、路線、照片存在 Firebase（Firestore，台灣機房 asia-east1），只有成員名單上的 Google 帳號讀得到；同步到手機後離線也能看。
- 登入只要求 **email 與基本資料**，App 不會存取任何人的 Google 雲端硬碟。
- `private/` 放含個資的案件檔，已列入 `.gitignore`，**不要提交、不要部署**。

## 雲端同步與權限（Firebase）

- **登入**：底部「案件」→ 頁面下方「同步與登入」→「以 Google 登入」。
- **切換案件**：底部「案件」（或點頂部案件名稱）打開「案件目錄」（`#/list`），可搜尋、依狀態篩選，一次顯示 20 個、其餘按「顯示更多」；每個案件的「⋯」有編輯、案件設定、上傳雲端、刪除。登入狀態存在手機，之後離線也維持。
- **權限**：由 [firestore.rules](firestore.rules) 在伺服器端強制執行：
  - 只有 `members` 名單上的帳號（加上寫死在規則裡的第一位管理員 `ben901227@gmail.com`）能讀寫案件、路線、照片。
  - 只有管理員能管理名單、刪除案件、看所有人的使用記錄；隊員只能寫自己的使用記錄、只能刪自己上傳的照片。
- **管理員**：⚙︎ 設定 →「管理成員與記錄」可加入／移除成員、改角色、看各手機的使用記錄、匯入舊的案件 JSON。
- **被移出名單**：對方的手機下次連線時就讀不到，並自動清除手機上的雲端案件與離線快取。若手機一直不連線，已下載的資料仍會留著。
- **即時同步**：有網路時，別人更新的案件、路線、照片會自動出現；離線時的修改由 Firestore 排隊，連線後自動上傳。路線每條分開存，多人同時編輯不會互相覆蓋；案件內容同時編輯時以最後儲存的為準。
- **照片**：在手機上壓縮成長邊 1280px、約 300 KB 內（另存約 30 KB 縮圖），直接存在 Firestore（每張上限 700 KB）。免費額度 1 GiB 約可放 3,000 張。手機離線快取不設上限，看過的照片沒網路也能看。
- **資料結構**：`cases/{id}`（案件）、`cases/{id}/routes/{id}`、`cases/{id}/photos/{id}`、`logs/{帳號_手機代號}`、`members/{email}`。Firestore 不支援「陣列中的陣列」，寫入時由 [js/lib/fsCodec.js](js/lib/fsCodec.js) 自動轉換。

### 一次性設定（已完成，供日後重建參考）

1. Google Cloud 專案建立 OAuth 用戶端 ID（網頁應用程式），已授權來源加入部署網址與 `http://localhost:5173`。同意畫面只需要 `openid`、`email`、`profile`。
2. 在同一個專案啟用 Firebase：Authentication 開啟 Google 登入；Firestore 建立在 `asia-east1`（正式版模式）。
3. 把 Firebase 網頁設定與用戶端 ID 填進 [js/config.js](js/config.js)；第一位管理員的 email 同時寫在 `js/config.js` 和 `firestore.rules`。
4. Firebase 網頁金鑰（`js/config.js` 的 `apiKey`）是公開識別碼，不是密碼，網頁一定看得到；已在 Google Cloud →「API 和服務」→「憑證」→「Browser key (auto created by Firebase)」限制只接受這些網站：`https://ben901227.github.io/*`、`http://localhost:5173/*`、`https://escue-offline-test.firebaseapp.com/*`。**換網址時要一起加進去**，否則 App 會連不上。
5. 部署權限規則：

```bash
npx firebase deploy --only firestore:rules
```

## 規劃搜救路線（可離線）

「地圖」右側的路線按鈕 → 在地圖上依序點出路線（可「復原」上一點）→「完成」→ 填名稱、負責隊伍、顏色、備註 →「儲存並上傳」。

- 底圖已下載的範圍內完全離線可用；路線長度即時顯示。
- 每條路線分開存在雲端，連線時直接上傳，離線時先存手機、連線後自動上傳，全隊會自動收到。
- 點路線可「編輯」（接續或復原點）、匯出 GPX 給 GPS 裝置，或刪除。「任務」頁列出所有路線，點一下跳到地圖。
- 目前為手動描點，不會自動沿山徑吸附，也沒有離線高度資料，長度為水平距離。

## 設定頁

- **案件設定**（`#/case`）：只跟目前案件有關——裝備清單，以及到編輯頁各分區的捷徑（無線電頻道與分組、失聯者、搜索範圍等）。從摘要頁底部、任務頁、案件「⋯」選單進入。
- **一般設定**（右上角齒輪）：帳號與登出、外觀（自動／淺色／深色）、App 版本與更新、使用教學；管理員另有「管理成員與使用記錄」。

## 裝備清單

摘要頁最下面「案件設定」（或任務頁「編輯裝備清單」）可依案件新增、刪除、排序項目與分類，或從東搜預設清單／其他案件複製。

- 「儲存並上傳」：立即套用到這支手機的任務頁（已勾選的項目會保留勾選），並上傳到雲端，全隊會自動收到。

## 使用記錄

App 會在手機本機記下錯誤（程式例外、未處理的 Promise）、登入與同步、上傳結果、離線待上傳、照片、成員變更、版本更新、離線地圖下載、航跡匯入失敗、定位問題與網路連線變化，最多保留 500 筆。登入後有網路時會自動上傳到 Firestore 的 `logs`（每支手機一份、最多每 10 分鐘一次），只有管理員看得到全部。設定頁不顯示使用記錄，隊員不用操作；管理員在「管理」頁查看。

## 本機執行

```bash
npm run serve
```

開啟 http://localhost:5173 。Service Worker 需要 `localhost` 或 HTTPS。

## 測試

```bash
npm test
```

涵蓋 TWD97 轉換（與 proj4 對照，誤差 < 1 cm）、GPX/KML 解析、案件檔驗證、使用記錄格式、Firestore 資料轉換、版本一致性。

權限規則用 Firebase 模擬器測試（需要 Java）：

```bash
npm run test:rules
```

驗證：未登入／非成員／email 未驗證讀不到；隊員不能刪案件、不能改名單；被移出名單後立刻讀不到；照片大小與上傳者限制；使用記錄只能寫自己的、隊員看不到別人的。

## 部署（例：GitHub Pages）

**改版流程**：改完先在本機（`npm run serve`，http://localhost:5173）讓需求提出人驗證，確認沒問題才 commit、push 上線。

**改版檢查清單**：只要畫面或操作有變，**同一次改版就要一併更新使用教學 [guide.html](guide.html)**（步驟說明、手機示意圖、按鈕對照表、常見問題），教學是給不熟手機的隊員看的，不能跟 App 對不上。

把專案（不含 `private/`）推到 GitHub repo，在 Settings → Pages 選分支即可。任何 HTTPS 靜態主機都可以。

**每次修改 App 檔案後，把 `sw.js` 的 `VERSION` 和 `js/version.js` 的 `APP_VERSION` 一起加 1（格式 `v0.0.xx`；`APP_CHANNEL` 標示「測試版」，正式上線時清空）**（`npm test` 會檢查兩者一致）。推上 GitHub 後 Pages 的 CDN 需要幾分鐘才完全更新，這段時間手機更新可能失敗，App 會提示「更新失敗，請稍後再試」並記入使用記錄；新增檔案時也要加進 `sw.js` 的 `SHELL` 清單，否則離線時會缺檔。隊員打開 App 時，若有新版會在頂部提示「有新版本」，設定頁也能看目前版本並立即更新。

## 隊員使用流程

1. 有網路時開啟網址 → 加到主畫面（iPhone：Safari 分享 →「加入主畫面」）。
2. 底部「案件」→「同步與登入」→ 以 Google 登入（管理員要先把你的 Gmail 加入成員名單）；案件目錄可切換案件。
3. 「地圖」→ 下載鈕存好搜索範圍圖磚；圖層鈕可匯入 GPX/KML 航跡；路線鈕規劃搜救路線。
4. 進山後：「定位」頁看 TWD97 座標、複製回報字串、打點；地圖長按可加標記、拍照標在該位置，或補上待補座標。

## 製作新案件

**建議用 App 內的案件編輯器**：案件目錄按「＋ 新增案件」，或在案件目錄的「⋯」／摘要頁底部按「編輯案件資料」。

- 依「東搜搜救紀錄 v1.1」段落分區填寫；穿著、聯絡人、行程、分組、每日紀錄、標記等可逐筆新增、排序、刪除。
- 座標欄可輸入「緯度, 經度」或「TWD97 X Y」，也可按 📍 在地圖上點選；搜索範圍按 🗺 用地圖框選。
- 填寫中自動存草稿，離開頁面不會遺失。
- 案件代號由程式自動產生（通報日期＋4 碼，例如 `2026-10-11-k3x9`）。
- 按「儲存並上傳」會存到手機並上傳到雲端，全隊自動收到；離線時先存手機，連線後自動上傳。
- 已建立的案件可在編輯頁最下方上傳「失聯者照片」或「現場照片」。

管理員也可以複製 `cases/template.json`，依 `cases/schema.md` 填好後在「管理」頁匯入。
